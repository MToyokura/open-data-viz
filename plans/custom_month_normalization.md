# 消費者物価指数の基準月を選べるようにする

## 目的

`/consumer_price_index` で、公表指数の表示と、選んだ月を100とする表示を切り替えられるようにする。後者では、同じ月からの物価変動を品目・地域ごとに比較できる。

同一系列の公表指数を使い、各月の表示値を `その月の指数 / 選んだ月の指数 × 100` で求める。表示値が105なら、選んだ月に比べて約5%上昇したと読める。品目構成やウエイトは公表系列に従い、地域間では物価の変化率を比較する。生鮮食品などの単月を起点にすると、季節性や一時的な値動きが比較に影響する。[CPI 2025年基準ガイド 第1・2・3・4・6節](../data_preparation/inspections/consumer_price_index/CPI_2025_BASE_GUIDE.md)

## 画面の動作

- 初期表示は既存の「2025年基準」とする。「最新月基準」ボタンを「基準月を選ぶ」に改め、この表示を選ぶとグラフの上に「基準月」のラベル付き選択欄を出す。
- 選択欄には「最新の共通月（自動）」と、描画対象の全系列に有限かつ正の指数がある月を新しい順に並べる。初回は自動を選び、既存の最新共通月の表示を再現する。実際に使う月を「2025年4月＝100（公表CPIを換算）」のようにグラフ付近に示す。
- 品目・地域の変更後も、指定月が共通して使える場合は維持する。読み込み完了後に指定月が使えなくなった場合は、その月を保持し、換算グラフの代わりに「選んだ月に値がない系列があります。別の月を選んでください」と表示する。選択欄から有効な月または自動に戻せるようにする。
- 一つの組み合わせに系列全体のデータがない場合は既存の一覧表示で知らせ、候補は描画対象の系列から求める。描画対象はあるが共通月がない場合はその旨を表示し、「2025年基準」に戻れるようにする。取得中や取得エラーは既存の状態表示を使う。
- 「2025年基準」へ切り替えても指定月はページ内で保持する。既存のリセット操作で月指定も自動に戻す。グラフのズーム範囲で候補や基準月を絞らない。

## 実装手順

1. [transformData.js](../frontend/src/routes/consumer_price_index/utils/transformData.js) の既存の最新共通月判定を拡張し、日付と系列別の値マップから利用可能な月の一覧を求める。同じ一覧を選択肢と分母の検証に使い、自動時は一覧の先頭、手動時は指定月を使う。無効な指定月や共通月なしの場合は換算グラフを生成しない。
2. 同じ変換処理で、表示対象の各系列をその系列自身の基準月で割る。基準月より前の観測値も表示し、欠測点は `null` のままにする。計算値は丸めず、ツールチップで既存どおり小数第1位に整形する。上位分類にも公表済み分類指数を使う。
3. [+page.svelte](../frontend/src/routes/consumer_price_index/+page.svelte) に月指定の `$state` を追加し、読み込み済みの描画対象系列と月指定から `$derived` でグラフと有効月を求める。既存のボタン、空状態、データ説明を更新し、選択欄は読み込み完了後に操作できるようにする。データ説明には、各系列の選択月を100に換算した値であることと、都市間の価格水準差の比較には使えないことを記載する。
4. データ取得と配信形式は既存のままとする。2024年以前を含む系列は、実装時に配信元で公式の接続系列であることを確認する。長期の比較は接続済みの公表値に基づき、各時期の品目構成・ウエイトが2025年基準で再計算されていると受け取られないよう説明する。前月比・前年同月比は今回の追加対象外とする。

## 完了条件

- 単一系列で105.0の月を100にしたとき、110.2の月が約105.0と表示される。複数系列では同じ基準月にすべての線が100を通り、各系列固有の分母が使われる。
- 自動では最新の共通月が選ばれる。欠測、ゼロ、負値、非有限値を含む月は候補から外れ、基準月以外の欠測点は線の切れ目として残る。共通月なしや指定月が無効になった場合に、誤った基準月や `NaN` を表示しない。
- 系列の追加・削除、読み込み、表示切替、リセットを通じて、基準月の表示と計算が一致する。2025年基準の表示値は公表指数と一致する。キーボードとモバイルでも月を選べる。
- 変換処理は Vitest で検証し、画面の操作はブラウザで確認する。`frontend` で `npm run check` と `npm run test:unit -- --run` を実行する。
