# 年齢階級・雇用形態・教育・性別ページの初期表示と属性比較

## 目的

`/workers_by_age_employment_type_education_sex` を開いた直後に有効な系列とグラフを表示し、固定した条件に対して年齢階級・雇用形態・教育・性別のいずれかを並べて比較できるようにする。操作感は `asset_distribution` の初期系列表示と属性比較を参考にする。

## 現状

- 選択肢の初期値は各分類の先頭コードだが、ページ表示時には系列を追加せず、「系列を追加」を押すまでグラフが出ない。
- `options.series` に公開済み系列のコードとファイルパスが並んでいる。選択条件の組み合わせが一覧にあるかをフロントエンドで判定できる。
- 現在は利用者が選択条件を変えて系列を個別追加し、複数系列を比較する。`asset_distribution` のような、比較属性と区分を選ぶ専用 UI はない。
- 系列データは `fetchSeries` で個別取得し、取得中・失敗・再試行・削除を表示する。

## 方針

変更は `frontend/` のみで行い、`data_preparation/`、生成データ、配信形式は変更しない。比較対象の存在確認には読み込み済みの `options.series` を使い、各対象系列のデータは既存の `fetchSeries` で取得する。

### 初期状態

1. `options.json` の読み込み完了後、`options.series` の先頭にある有効な系列を初期系列にする。
2. その系列の4コードを選択欄にも反映し、選択欄とグラフの条件が一致するようにする。分類の先頭値の組み合わせが未公表でも、空のグラフにならない。
3. 初期系列を既存の追加系列状態に登録して取得を始める。読み込み中・取得失敗時は既存の状態表示と再試行操作を使う。
4. 選択条件を変えた場合は現在と同じく「系列を追加」で追加できる。初期系列も既存の削除操作で消去できる。

### 属性比較

1. 系列選択欄の近くに「属性を比較」コントロールを追加し、比較属性（年齢階級、就業状態／雇用形態、教育、性別）を選べるようにする。
2. 比較属性以外の3条件は通常の選択欄の値で固定する。比較属性の選択欄は比較中に無効化し、比較対象のコードはチェックボックスで選択する。
3. 各比較区分について、`options.series` に同じ固定条件とその区分コードを持つ項目があれば選択可能とする。該当項目がなければ無効化し、「この条件の系列はありません」と理由を示す。
4. 比較属性を選んだ時点で、利用可能な区分を初期選択する。利用者はチェックボックスで表示する区分を絞り込める。系列が1つ以下なら比較グラフを表示せず、追加で選択できる区分があるか案内する。
5. 選択されたインデックス項目を既存の取得・表示モデルに渡し、各系列を取得して年次推移グラフに重ねる。系列ラベルには比較属性の区分名を使う。教育は既存の `labelFor` と同じ区別を維持し、コード `03`・`04` に「在学中 >」、`07`・`08` に「卒業 >」を付ける。チェックボックスにも同じ名称を使い、同名の学校区分を識別できるようにする。
6. 通常表示と比較表示の系列状態を分ける。比較開始時に通常表示の系列一覧と4条件を保持し、比較中は比較対象だけを一覧・グラフ・データ注記に表示する。通常表示で追加した別条件の系列は比較グラフに混ぜない。
7. 「比較しない」に戻したら、保持した4条件と通常表示の系列一覧を復元する。比較中の固定条件の変更は通常表示には引き継がない。この動作を比較 UI に説明する。開始時の選択条件が未公表でも別の系列を自動追加せず、元の一覧と「該当するデータがありません」の表示に戻す。元の一覧が空なら空のまま復元する。

### 比較中の操作と状態遷移

- 「系列を追加」は比較中に無効化する。比較対象の追加はチェックボックスで行う。
- 比較系列の削除は、その区分のチェックを外す操作と同じにする。「すべて消去」は比較区分の選択をすべて解除する。どちらも保持している通常表示の系列一覧には作用しない。
- 比較中に他の3条件を変更したときは、選択済みコードと新しい条件で利用可能なコードの共通部分だけを維持する。新たに利用可能になった区分は自動選択しない。0区分または1区分になった場合も選択状態を維持し、比較グラフを隠して追加選択の案内を表示する。
- 比較属性を別の属性に切り替えるときは、その時点の選択欄の値を新しい固定条件として使い、新しい比較属性で利用可能な区分を初期選択する。無効化していた選択欄の値は書き換えない。通常表示に戻すための4条件と系列一覧は、比較開始時のものを維持する。
- 読み込み中・失敗・再試行は系列ごとに表示する。チェック解除、条件変更、比較属性の変更、比較解除で対象から外れた取得結果は比較一覧に反映しない。既存のリクエスト識別子による照合を維持し、同じ系列を選び直した場合も古い応答が新しい取得状態を上書きしないようにする。
- 保持している通常表示の取得処理は通常表示の状態だけを更新する。比較表示と通常表示で同じ系列を扱う場合も、ラベルや削除、取得結果が相互に干渉しないようにする。

  - 通常表示と比較表示の系列状態を分け、条件と通常系列の復元、削除・全消去とチェック状態の同期、取得結果の反映先を実装する。
  - 教育区分の表示名を共通化し、通常系列・比較系列・チェックボックスで在学中／卒業を一貫して区別する。
- `frontend/src/routes/workers_by_age_employment_type_education_sex/constants/types.js`
  - 新しいサーバー形式を導入しない限り、型定義の変更は不要。必要であればフロントエンドの比較状態用型だけを追加する。
- `frontend/e2e/workers-by-age.test.js`
  - 初期表示で既定系列が取得されること、比較属性・区分を選ぶと対応系列が表示されること、存在しない組み合わせが選択できないことを確認するケースを追加する。
  - 初期取得が加わるため、既存ケースのリクエスト件数・順序と系列一覧の期待値を見直す。
  - 異なる条件の手動系列を複数追加して比較を開始し、比較中は対象系列だけが表示され、解除後に元の4条件と一覧が復元されることを確認する。開始時の選択条件が未公表の場合と、元の一覧が空の場合も含める。
  - 比較中の削除・全消去がチェック状態と同期し、固定条件変更後は利用可能な選択だけが残ること、比較属性切り替え時は新しい属性の区分が初期選択されること、選択が1つ以下ならグラフが表示されないことを確認する。
  - 教育コード `03` と `07` を比較し、チェックボックスと凡例で「在学中 > 短大・高専」「卒業 > 短大・高専」を識別できることを確認する。
  - 比較中の取得失敗・再試行と、条件変更・チェック解除・比較解除の後に届く応答を確認し、古い応答による系列の復活や状態の上書きがないことを確認する。

## 注意点

- `options.series` の順序が初期系列の選択に影響する。現行の生成結果で先頭が安定していることを確認し、並びに意味がない場合は、分類順に基づく選び方をフロント側で明示する。
- 現在の `options.series` は有効な系列の存在を示す一覧であり、実データがすべて欠損値の系列かどうかまでは分からない。欠損系列も比較対象に残し、現行グラフの注記表示に任せる。
- 比較対象を多数選ぶと同時取得数が増える。年齢や雇用形態の全区分程度を想定し、必要なら同時リクエスト数や選択上限を設けるかを実装時に判断する。
- 利用可能系列がなくなった場合と、利用可能な区分はあるが未選択の場合を区別して案内する。

## 完了条件

- ページを開いて選択肢の読み込みが終わると、有効な初期系列のグラフと選択条件が表示される。
- 任意の1属性について、他の条件を固定したまま複数区分を同じグラフで比較できる。
- 公表系列がない区分は理由付きで選択不可となり、系列取得エラー・再試行・削除が既存機能と整合する。
- 比較中の表示には選択した固定条件の系列だけが含まれ、削除・全消去とチェック状態が一致する。比較解除時は開始時の4条件と通常系列一覧が復元される。
- 教育の在学中／卒業に同名区分があっても、チェックボックスと系列ラベルから識別できる。
- 変更範囲は `frontend/` に限られ、`data_preparation/` とデータ形式は変更されない。
