# frontend の不統一を解消する計画

作成日: 2026-11-15

## 目的・調査範囲

UI、配置、出典表記の差分と、画面内で重複する情報を、小さな修正単位に分けて順番に解消する。今回は計画のみを作成し、frontend の実装は変更しない。

対象はトップページ、可視化5画面（小売価格、雇用者数、純資産分布、野菜の産地リレー、社会保障給付費収支）、エラーページ、共通コンポーネント、`frontend/static/global.css`、既存テスト。

以下はソースコードの確認に基づく棚卸し。ブラウザでの表示確認、スクリーンショット比較、外部出典の内容・利用条件の検証は未実施。コード上で確認できた差分と、実画面で確認する項目を分ける。出典の正しさそのものは表記の統一と別に確認する。

## 既存の共通化と、残すべき違い

- 可視化5画面は `WorkspaceHeader`、`ReferencePanel`、`LicenseLink` を利用済み。出典表にも「統計名」「表題」「統計表ID」「対象年／期間」という共通の基本形がある。
- `global.css` に色・余白・枠線・角丸・コントロール高さ、ワークスペース、比較一覧、グラフのスクロール枠がある。新たな体系を作る前に既存の共通化を利用する。
- 小売価格は地域選択で即時反映、雇用者数・純資産分布は「系列を追加／属性を比較」。操作の目的が違うため、同じ選択方式に揃えること自体を目標にしない。
- 地図の拡大縮小、サンキー図の横スクロール、棒グラフの向き、階級数に応じた高さは用途に応じて残す。統計の単位、欠損・秘匿・集計除外の意味も変えない。
- トップページは一覧・紹介、可視化ページは作業領域。最大幅や見出しサイズの違いをすべて不統一とは扱わない。

## 統一方針（修正時の基準案）

1. 共通する役割のUIには同じ見た目、文言、状態の伝え方を使う。例外には理由を記録する。
2. 狭い画面の順序は、比較系はグラフ→条件→出典、制度選択系は選択→図→出典、地図系は地図→詳細・条件→出典を基準に確認する。出典は条件・説明の後に置く。
3. 出典パネルの基本順序は「利用上の注意→出典」。操作方法は原則として操作部付近に置き、詳細説明への導線を設ける。
4. 出典は元資料を特定できる情報とリンクを基本とし、全画面に同じ項目を必須表示しない。提供機関・統計名・表題・統計表IDとリンク・期間・単位・加工説明などから、その画面で必要な項目を選ぶ。同じ項目を表示する場合は名称と相対的な順序を揃える。値は確認できたものだけ記載し、表示が必要な情報を取得できない場合は空欄ではなく状態を示す。
5. 複数表は表題・ID・リンクの対応がわかる単位で表示する。地図など統計以外の出典は別ブロックに分け、帰属表示を維持する。
6. 日本語の文言を基本とし、未選択・取得中・取得失敗・該当データなし・秘匿／欠損を区別する。
7. 文字・背景・枠線・余白は既存トークンを優先し、チャート固有の寸法と共通UIの装飾を分ける。

8. グラフ・数値・選択欄に明記され、意味が明白な情報は、出典や説明から重複を削除する。たとえば産地リレーの数値に `t` が表示されている場合、出典表の「単位 t」は削除対象とする。数値の桁などから単位を推測させない。元データと表示の単位が異なる場合の換算、集計対象、欠損・秘匿・除外の扱い、帰属表示など、表示データだけでは判断できない情報は残す。詳細が必要だが常時表示は不要な説明は折りたたみを検討し、単なる重複は折りたたまず削除する。

## 推奨する実施順

1. **QA-01**: 現状を撮影・記録し、テストの前提を合わせる。下記のブラウザ確認で追加の差分が見つかったらIDを追加する。
2. **REF-03 → REF-01 → REF-02 → REF-04 → REF-06 → REF-05**: 最初に産地リレーの「単位 t」などの重複を削除し、全画面で残す情報を決める。必要な説明・到達性・配置を整えてから描画を共通化する。
3. **UI-01 → UI-02 → UI-03**: 状態と操作の意味を統一する。
4. **LAY-01 → LAY-02 → LAY-03**: 切替幅、表示順、グラフ領域を順番に調整する。
5. **VIS-01 → VIS-02 → UI-04**: 見た目と周辺画面を整える。

1項目ずつ、対象・変更内容・検証結果をレビューし、完了条件を満たしてからチェックする。共通CSSの変更時は全5画面へ影響するため、対象画面だけで完了にしない。

## 修正ごとの確認方法

- 基本幅: 320px、390px、768px、1024px、1440px。加えて変更対象のメディアクエリ境界の直前・直後を確認する。
- 状態: 初期表示、未選択、取得中、成功、複数系列、該当なし、一部失敗、全体失敗、再試行。秘匿・欠損は対応する画面で確認する。
- 操作: 条件選択、追加・削除・全消去、モード切替、折りたたみ、画面幅変更、表示方法切替、グラフの向き変更、地図・サンキーの詳細表示。
- 出典: 残した項目の名称・相対的な順序、表題とID・リンクの対応、選択した年・品目との一致、単位・加工説明、長いURLの折り返し、帰属表示、取得失敗時の到達性。削除した情報がグラフ・数値・選択欄で確認でき、折りたたみや表示切替後も解釈に支障がないこと。
- アクセシビリティ: キーボード操作、フォーカス、ラベル、状態通知、表示順とDOM順、文字拡大時の欠け。
- コードを変更した場合は `cd frontend` で `npm run check` と `npm run build`。操作・状態を変更した箇所は関連するユニット／E2Eを実行する。最終的には `npm run test:unit -- --run` と `npm run test:e2e` で横断確認する。
- レイアウト・装飾だけの変更はスクリーンショットと操作確認を中心にし、CSSの値をなぞるだけのテストは追加しない。
