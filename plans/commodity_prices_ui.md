# Commodity prices UI parity with consumer price index

## Target behavior

Use `/consumer_price_index` as the interaction and layout reference for `/commodity_prices`. Users can search for and select several products and cities, remove individual product–city pairs, and compare the selected series on a single chart. Prices open in yen. Choosing a reference month scales each series so its own price in that month equals 100. Keep the commodity survey attribution, item specifications link, and license visible.

The workspace and line chart are already shared or styled the same way. The main gaps are the commodity page’s product radio buttons, its per-product city selection, its generic chart empty state, and the absence of a reference-month control. [CPI page](../frontend/src/routes/consumer_price_index/+page.svelte) · [Commodity page](../frontend/src/routes/commodity_prices/+page.svelte)

## Implementation

1. **Match the CPI selectors and selected-series list.** Replace the active product and per-product city map with selected product codes, selected area codes, and excluded pair keys. Derive the active series from the product × area combinations minus exclusions, keyed by `cat02Code:areaCode`. In `Selectors.svelte`, use independent searchable checkbox lists with commodity examples such as `食パン` and `札幌市`. Keep selections when searches hide options. Show actual checked state when only one list has selections, and show a mixed state when only some pairs for a product or city are active. Removing a series excludes only that pair. Checking its product or city again restores the applicable excluded pairs. `すべて消去` clears both selections, exclusions, and the reference month, including when only one selector has a selection. [Commodity selectors](../frontend/src/routes/commodity_prices/Selectors.svelte) · [CPI selectors](../frontend/src/routes/consumer_price_index/Selectors.svelte)

2. **Load and report the state of each active pair.** Drive requests from the full set of active combinations and deduplicate in-flight requests by pair key. Reuse successful responses and known empty results when users reselect a pair. Replace the page-wide fetch generation with keyed request handling so edits to one pair cannot invalidate another pair’s response. A removed or cleared pair may finish fetching, but its response cannot restore its selection or chart line. Keep the lookup retry and per-series retry controls. Treat a 404 or a series without any numeric observations as empty and other request failures as retryable. Match CPI’s chart states for no selection, loading, failed series, and no plottable data. Draw the available lines after all active pairs resolve as loaded or empty. [Commodity fetcher](../frontend/src/routes/commodity_prices/utils/fetchCommodityPrices.js)

3. **Add the reference-month selector and slider.** In `utils/transformData.js`, derive canonical `YYYY-MM` keys from the commodity e-Stat time codes such as `2025000303`, align the series by month, and preserve missing observations as gaps. Offer months with finite, positive prices across every plottable selected series. Use `価格（円）` as the default option and label the rebased axis `共通基準月＝100`. Calculate each rebased point as `price / priceAtReferenceMonth × 100`. Keep the dropdown and slider synchronized and show the slider when more than one common month exists. If changing the selection invalidates the chosen month, show the CPI-style explanation. Offer any remaining common months and keep the yen option selectable even when there are no common months. Explain the calculation in `データについて` alongside the existing commodity source and unit notes. [Commodity transform](../frontend/src/routes/commodity_prices/utils/transformData.js) · [CPI transform](../frontend/src/routes/consumer_price_index/utils/transformData.js) · [Commodity reference](../frontend/src/routes/commodity_prices/Reference.svelte)

4. **Match responsive and chart behavior.** Keep the side-by-side desktop workspace and chart-first mobile layout. Use `useResponsivePanels` with `{ mobileOpen: true }` so the selector and comparison panels start open on mobile, as in CPI. Place the reference-month controls above the chart on desktop and below it on mobile. Follow CPI’s selected-row spacing and wrapping. Keep the shared `LineChart.svelte` renderer, fit/scroll controls, and time zoom. Use the existing lookup files and per-pair JSON paths. [Responsive panels](../frontend/src/lib/useResponsivePanels.svelte.js) · [Shared line chart](../frontend/src/routes/commodity_prices/LineChart.svelte)

## Verification

- Extend the commodity Playwright test with two products and two cities. Verify selecting a city first, four resulting pairs, search without selection loss, single-pair removal, mixed checkbox states, restoration, and reset. Use realistic e-Stat time codes in its mocked series responses. [Existing Playwright test](../frontend/e2e/e2e.test.js)
- Mock a delayed response, a 404, and a retryable failure. Confirm that a pending pair can be removed without reappearing, that another pair finishing during a selection change still loads, and that retry updates only the failed pair. Check all-empty selections as well as loaded/empty mixtures.
- Extend the commodity transform tests for raw yen values, month decoding, common-month eligibility, rebasing to 100, and gaps for missing values. In the browser, verify dropdown/slider synchronization and recovery when a change in selected series invalidates the reference month. [Existing transform tests](../frontend/src/routes/commodity_prices/utils/__tests__/transformData.test.js)
- Compare commodity and CPI at desktop and mobile widths. Check panel defaults and order, keyboard access, long series labels, and fit/scroll mode without page overflow. Run `npm --prefix frontend run check`, `npm --prefix frontend run test:unit -- --run`, and `npm --prefix frontend run test:e2e -- e2e.test.js`.
