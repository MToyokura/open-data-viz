# 実装計画：属性別に見られる純資産額階級別世帯数

## 目的

総務省「令和6年全国家計構造調査」から、純資産額階級別世帯数を既存サイトに追加する。APIメタデータと統計データを調査し、選択可能な分類軸・区分を特定したうえで、利用者が条件を組み合わせてグラフを見られるようにする。グラフの階級名と区分は統計データに従う。

純資産額階級別世帯数を表示する新しいページとデータパイプラインを追加する。主グラフは統計データに実際に含まれる純資産額階級ごとの世帯数とし、属性別の絞り込み・比較に対応する。

## データソース

第一候補は、令和6年全国家計構造調査「年間収入・資産分布等に関する結果［分布指標］」表7-131-1-1、e-Stat 統計表ID `0004056120`「資産額階級別世帯数」である。

- [e-Stat 表7-131-1-1](https://www.e-stat.go.jp/dbview?sid=0004056120)
- 調査年：2024年
- 地域：全国
- 必要な値：金額階級ごとの世帯数と、表に含まれる分類軸・各分類区分

取得実装に入る前に `getMetaInfo` と公式表の注記を確認し、表の「資産額階級」が世帯の「純資産総額（純金融資産＋住宅・宅地）」の階級であること、階級境界・単位・世帯数の表章方法を確定する。異なる概念の総資産額や等価資産額の階級であれば、この表を使わず、純資産総額階級別の世帯数を直接表章する適切な表を探す。

棒グラフには統計データに含まれる純資産額階級をそのまま表示する。階級の追加、統合、分割は行わず、統計データに含まれない金額帯を独自に作らない。平均、十分位、再掲階級など通常の階級と重複する項目は、階級別世帯数の棒に混ぜない。選択可能な分類軸と区分はAPIメタデータおよび統計データを inspection して確定する。HTML画面の表示項目だけから、APIで選択可能な軸・区分を推定しない。

## 既存アーキテクチャに合わせた方針

- e-Stat API の取得・整形は `data_preparation/` の Rust CLI に実装する。既存の `getMetaInfo` / `getStatsData` 共通処理と `ESTAT_APP_ID` の読み込みを再利用する。
- API ID はデータ生成時だけ使い、生成 JSON やフロントエンドに保存しない。
- 配布データは `data_preparation/output/` に生成する。ローカルではルートの `npm run serve` がこのフォルダを配信し、本番では既存の `VITE_STORAGE_BASE_URL` が指す静的データ置き場から取得する。ページ表示時に e-Stat API を直接呼ばない。
- SvelteKit の静的アダプターと既存の ECharts 遅延読み込みを維持する。
- `/asset_distribution` ページを新設し、画面タイトル、トップページのリンク、出典、データ取得・検証処理を追加する。

## 実装手順

### 1. 表の階級・分類軸・集計条件を確認

`getMetaInfo` で表7-131-1-1の分類情報を取得し、メタデータと `getStatsData` の応答を inspection して、実際に選択・取得できる分類軸と区分を特定する。e-StatのHTML表示は内容の照合に使い、APIの選択肢を決める根拠にはしない。少なくとも以下を確認する。

- 表章項目「世帯数」
- 地域「全国」
- 時間軸「2024年」
- 純資産総額に対応する階級分類と全階級のコード・名称
- APIメタデータに含まれる全分類軸と、それぞれの全区分・コード・名称
- 各分類軸の全体・総数にあたる選択肢、通常階級、十分位、再掲などの項目種別
- 各軸の公式表示順、初期値に使う総数コード、絞り込みに使う軸と金額階級軸の区別
- 比較で同時に表示できる、互いに重複しない区分集合。金額階級と十分位、親区分と子区分、再掲は別の集合として扱う
- 実際に公表される属性の組み合わせと、構造上公表されない組み合わせ。その判定根拠
- 世帯数の単位、推計値か標本数か、秘匿・欠損・注記記号の意味

分類コードを推測で固定しない。APIメタデータと応答から分類軸ごとのコード・ラベル・選択可能な区分を確認し、inspection 記録に残す。HTML画面で見える項目とAPIで取得できる項目の差も記録する。属性の「全体」は公式表にある総数区分で表し、各区分を足して総数を作らない。属性別の値を合算して重複計上しない。対象表に必要な全体値がない場合や、資産階級の概念が純資産総額でない場合は、表選定をやり直して根拠を記録する。

**成果物候補**：`data_preparation/output/asset_distribution/meta_data/get_meta_info.json`、`data_preparation/output/asset_distribution/raw_data/get_stats_data.json`。

### 2. Rustで階級別・属性別世帯数を検証・整形

既存の Rust プロジェクトパイプラインを参考に `asset-distribution` コマンドを追加する。メタデータで特定したコードを使い、全国・2024年の対象データを分類軸と階級のコード・ラベルを保持して整形する。総数の系列だけに絞らず、属性の組み合わせごとの値も収録する。APIの取得件数上限がある場合は分割取得し、全件を取り込んだことを検証する。

配布データは `data_preparation/output/asset_distribution/manifest.json` と `items/` 配下の値チャンクで構成する。manifest には `schema_version`、メタデータ、分類辞書 `dimensions`、全組み合わせ `combinations`、チャンク一覧 (`chunks`) を含める。組み合わせごとの `items_file` で値ファイルを特定し、チャンク一覧にはファイルサイズと対象組み合わせを記録する。以下は論理構造の例であり、軸・区分コードや値は公表値ではない。

```json
{
  "schema_version": 1,
  "metadata": {
    "stats_data_id": "0004056120",
    "year": 2024,
    "area": "全国",
    "measure": "世帯数",
    "asset_basis": "純資産総額",
    "unit": "世帯",
    "source_url": "https://www.e-stat.go.jp/dbview?sid=0004056120"
  },
  "dimensions": [
    {
      "id": "<属性軸のAPI ID>",
      "label": "<公式の軸名>",
      "role": "filter",
      "order": 0,
      "total_code": "<公式の総数コード>",
      "default_code": "<公式の総数コード>",
      "categories": [
        {
          "code": "<公式区分コード>",
          "label": "<公式区分名>",
          "kind": "regular",
          "order": 0
        }
      ],
      "comparison_sets": [
        {
          "id": "<比較集合ID>",
          "label": "<金額階級などの表示名>",
          "category_codes": ["<公式区分コード>"]
        }
      ]
    }
  ],
  "combinations": [
    {
      "id": "<組み合わせID>",
      "dimensions": {
        "<属性軸のAPI ID>": "<公式区分コード>"
      },
      "status": "published",
      "reason": null,
      "items_file": "items/00000.json"
    }
  ],
  "chunks": [
    { "path": "items/00000.json", "combination_ids": ["<組み合わせID>"], "bytes": 1234 }
  ]
}
```

値ファイルの例（`items/00000.json`）：

```json
{
  "schema_version": 1,
  "items": [
    {
      "combination_id": "<組み合わせID>",
      "asset_class_code": "<公式の純資産額階級コード>",
      "count": null,
      "status": "suppressed",
      "raw_value": "<APIの原表記>",
      "annotations": ["<公式注記に基づく秘匿理由>"]
    }
  ]
}
```

分類辞書と状態の仕様：

- `dimensions` に全属性軸と純資産額階級軸を収録する。`role` は `filter` または `asset_class` とし、階級軸を属性の比較対象にしない。区分は `code`、`label`、`kind`、`order` を保持する。`kind` は `total`、`regular`、`decile`、`reprint`、`unknown`、`other` から inspection の根拠に従って設定する。
- 属性軸の `total_code` と `default_code` は確認済みの公式総数コードとする。純資産額階級軸ではこれらを `null` とし、通常階級を `order` の金額順で表示する。通常階級に含めない総数・不詳・再掲等も辞書に残し、表示対象を明示する。
- `comparison_sets` は inspection で相互に重複しないと確認した区分だけを列挙する。総数・再掲を部分集団と同じ集合に含めず、金額階級と十分位、親区分と子区分を同じ集合に混在させない。比較可能な集合のない軸では空配列とする。集合IDや種別はアプリ内の識別情報であり、公式コードと区別する。
- `combinations` は絞り込みに提供する全属性区分の組み合わせを対象とし、全属性軸のコードを保持する。`published` は公表対象、`not_published` は構造上の非公表とし、後者は公式資料等による判定根拠を `reason` に必須とする。応答に存在しないことだけを非公表の根拠にしない。
- `items` は公表対象の組み合わせと通常の純資産額階級の組ごとに一件を持つ。コードとラベルの対応は分類辞書を参照する。`not_published` の組み合わせには値を作らない。
- 値の `status` は `observed`、`suppressed`、`missing` とする。`observed` の `count` は非負の数値で、公式に0と表章された値もここに含む。`suppressed` と `missing` は `count: null` とし、原表記と公式に確認できた理由を保持する。数値に注記がある場合は数値を保持して `annotations` に注記を付ける。意味を確定できない記号は生成エラーとする。
- ページ分割の取得漏れや、非公表の根拠を確認できない応答上の欠落は生成エラーにする。取得漏れを `missing` や `not_published` に変換しない。

例中の分類軸、コード、区分名、世帯数は形式例であり、公表値ではない。実際の軸・階級・区分は API メタデータと統計データから特定し、HTML表示および公式資料と照合する。メタデータにない分類軸や区分を固定で追加しない。境界値は公式情報で確定できる場合だけ設定し、開放端の階級や負の純資産を含む階級は有限区間に見せず、公式名称をそのまま表示する。

検証条件：

- 対象階級がメタデータにある全ての通常階級と一致し、重複・欠落がない。
- すべて全国・2024年・世帯数であり、各値に対応する属性区分のコードとラベルが保持されている。
- 分類辞書のコード参照、種別、表示順、総数・初期値、比較集合が inspection 記録と一致する。各比較集合に重複する区分が含まれていない。
- 公表対象の組み合わせと通常階級の組が一意で、取得漏れ・重複がない。APIの総件数と全ページの取得件数・一意件数を照合する。構造上の非公表は根拠付きで区別し、全体値と部分集団の値が混ざっていない。
- 世帯数は仕様に沿った非負の数値として保持する。秘匿・欠損・注記値は0に置き換えず、状態と理由を保持する。
- 出力する階級が統計データに含まれる通常の階級と一対一で対応し、独自の統合・分割・再掲になっていないことを確認する。別の階級と重なる項目や十分位を階級として加えない。
- 絞り込み条件は分類軸ごとの公式区分コードで評価し、未選択の軸は公式の全体・総数区分を使う。部分集団を足して全体を作らない。
- API値を公式統計表と照合し、値の単位、丸め、推計世帯数としての扱いを記録する。

**成果物**：`data_preparation/output/asset_distribution/manifest.json` と同ディレクトリの `items/*.json`。既存の単一 `asset_distribution.json` は配信用生成物から外す。

### 3. 検証記録を残す

調査・照合の根拠を新しい `data_preparation/inspections/asset_distribution/` に記録する。

- `README.md`：調査日、統計表ID、対象条件、純資産総額階級と確認した根拠、APIメタデータと統計データから特定した分類軸・全区分・選択可否、分類辞書の種別・順序・総数・初期値・比較集合の根拠、公表対象と構造上の非公表の組み合わせの判定根拠、HTML表示との相違、全階級・属性組み合わせの API 値と公式表との照合、世帯数の単位・推計方法・丸め・秘匿の扱い、未確認事項。
- `samples/meta_info.json`：分類コードを追試できる `getMetaInfo` の応答標本。
- `samples/stats_data.json`：総数系列と属性区分の組み合わせを確認できる `getStatsData` の応答標本。
- `capture_manifest.json`：取得日時、統計表ID、フィルター、標本ファイルのチェックサム。

標本内の `appId` は保存前に `[REDACTED]` に置き換える。実測していない分類コードや値を記録せず、公式表との不一致や残る不明点も記録する。`inspections/README.md` に新しいテーマを追加する。

### 4. ページと属性選択・階級別グラフ

`/asset_distribution` に2024年の属性別純資産額階級別世帯数ページを新設する。ページは上記 JSON を読み込み、HTTP エラーや形式不一致を既存ページと同じ方法で表示する。

- タイトル例：「日本の純資産分布｜属性別・純資産額階級別の世帯数（2024年）」
- APIメタデータと統計データの inspection で選択可能と確認した分類軸ごとに選択 UI を用意する。選択肢と表示名は検証済みの JSON メタデータに基づける。
- 各属性軸を公式の全体・総数区分または一つの公式区分に設定し、複数軸を同時に組み合わせて絞り込めるようにする。初期値・表示順・総数の判定には分類辞書を使い、ラベルやコードの文字列から推測しない。
- 選択肢は `combinations` に従って制御する。単一系列の表示中は、現在の他軸の条件と組み合わせた結果が `not_published` になる選択肢を無効にし、理由を表示する。未掲載の組み合わせは、単一系列・比較のいずれでもデータ形式エラーとして扱う。公表対象で値が秘匿・欠損の場合は選択を許可する。
- 比較する属性軸を一つ選び、その軸の `comparison_sets` から一つの区分集合を選んで系列を作る。金額階級と十分位などは集合を切り替えて比較する。比較中はその軸の単一区分フィルターを無効にし、その保持値を値の取得や選択肢の可否判定に使わない。他軸の条件を比較集合の各区分に適用する。比較を終了するときは保持値で単一系列に戻し、その組み合わせが非公表なら全属性軸を公式総数の初期値に戻す。
- 比較中に他軸の選択肢を判定するときは、候補の区分と現在の残りの他軸の条件を固定し、比較集合の各区分について `combinations` を参照する。`published` の区分が二つ以上ある候補だけを選択可能にする。二つ未満の候補には比較に必要な公表系列数を満たさない旨と、該当する非公表理由を表示する。比較軸・比較集合の候補にも同じ系列数の判定を適用する。
- 他軸の条件で非公表になる比較区分は、理由を添えて利用不可と表示する。公表対象の区分は全階級が秘匿・欠損であっても系列として保持し、選択可否を判定する公表系列数に含める。数値を表示できない系列にはその旨を明示する。比較の開始時などに公表系列が二つ未満なら比較できない旨を表示し、単一系列表示を維持する。
- 「全体・総数」は公式の総数区分がある場合に使う。全区分の数値を合算して総数を作らず、重複する総数と部分集団を同時に系列表示しない。
- 分類軸・区分が多く比較系列を同時に表示すると読みにくい場合は、比較対象を一軸に限定して選択 UI で切り替える。小画面では選択 UI と凡例を操作・判読できるようにする。
- 公式の金額階級を縦軸、世帯数を横軸にした横棒グラフを表示し、金額順に並べる。
- 選択した条件における全階級を対象とし、世帯数と単位「世帯」を各棒のラベルまたはツールチップで確認できるようにする。比較系列を表示するときは階級ごとに系列を並べて比較できる。
- 統計データに含まれる公式階級をそのまま表示し、複数階級をまとめた独自の金額帯は作らない。
- 割合の併記は任意とする。表示する場合は、通常の純資産額階級が資産額判明世帯を重複なく網羅すると公式資料で確認でき、当該系列の全通常階級が `observed` で、世帯数合計が正の場合に限る。分母は当該系列の全通常階級の世帯数合計とし、「選択条件に該当する資産額判明世帯内の構成比」と表示する。不詳を除くこと、丸め済みの公表値から算出することを説明する。比較時は系列ごとに分母と表示可否を判定する。秘匿・欠損が一件でもある系列や合計が0の系列では割合を表示せず、理由を示す。観測できた階級だけの合計による再正規化や、「全世帯に占める割合」という表示は行わない。
- 秘匿・欠損値に棒を描かず、階級名と系列名に対応する「秘匿」「欠損」の状態・理由をツールチップ以外でも確認できるようにする。0として描かない。
- 狭い画面でも階級名と数値が読める高さ・余白にする。

### 5. 説明と出典

グラフの近くに調査年、純資産総額の定義、資産額階級の境界、表示する世帯数が推計値か調査標本数かを説明する。資産額不詳、秘匿値、開放端の階級、丸めの扱いを公式資料に沿って記載する。

出典は総務省統計局「令和6年全国家計構造調査」表7-131-1-1とし、統計表ID `0004056120` の e-Stat ページへリンクする。調査年と公表年を区別する。

### 6. データ配信

manifest と `items/` 配下のチャンクがローカルの `npm run serve` 経由で同じ相対パス構造のまま読み込める構成にする。本番の静的データ置き場には `asset_distribution/manifest.json` と `asset_distribution/items/*.json` を配置し、`VITE_STORAGE_BASE_URL` を基点に取得できるようにする。API ID は Actions のビルド環境やブラウザーに渡さない。

## 完了条件

- 表の定義と公式注記から、対象階級が純資産総額を表すことを確認している。
- 全国・2024年の全階級と、APIメタデータから特定した分類軸・区分の組み合わせを取得し、代表的な組み合わせを公式表と照合できる。
- inspection で選択可能と確認した複数の分類軸を組み合わせて絞り込み、さらに一つの分類軸を使った比較系列を表示できる。
- 比較中の他軸・比較軸・比較集合の選択可否は公表系列数で判定し、無効な単一区分フィルターの保持値に左右されない。非公表の比較区分がある場合、全階級が秘匿・欠損の系列がある場合、比較を終了する場合の動作を確認している。
- 配布JSONだけで軸・区分の表示順、初期値、総数、比較集合を決定でき、重複する区分を同時に比較表示しない。
- 非公表の組み合わせを理由付きで選択不可にし、取得漏れは生成エラーとして検出する。秘匿・欠損値を0と誤表示せず、単位と階級の定義が説明されている。
- 割合を併記する場合は、資産額判明世帯内の構成比として分母を説明し、通常階級の網羅性が未確認の場合、秘匿・欠損がある場合、分母が0の場合には表示しないことを確認している。
- 表示する階級が統計データに含まれる公式階級と一対一で対応し、独自の金額帯を作っていない。
- ページに属性条件を選べる UI、階級別世帯数の横棒グラフ、比較系列、数値、説明、出典リンクが表示される。
- API IDなしでページ表示ができ、JSON取得エラー時に利用者向けエラーが出る。
- ローカルのデータ配信と既存の静的サイト配置方針でページが動作する。

地域・年次の切替、ブラウザーからの e-Stat API 直接呼び出し、API データのページ表示時更新は行わない。世帯属性の絞り込み・一軸の属性比較は対象に含める。
