# 野菜リレーに産地・消費地域の Sankey 図を追加する計画

## 実現可能性

実現可能。現在の生成データには、品目・月・産地都道府県ごとの主要消費地域9区分の寄与値がある。たとえば `data_preparation/output/vegetable_production_relay/{品目キー}/details/{都道府県コード}.json` の各月に、`consumer_region_code`、`consumer_region_name`、`value_kind`、`raw_value` が含まれている。`reported` の値を数値化すれば、47都道府県から9消費地域への数量フローを作れる（最大423リンク）。

47都道府県の detail JSON は、月ごとに別ファイルではなく、品目ごとに各都道府県1ファイルで36か月分を含む。Sankey は初期表示や月選択のたびには取得せず、ユーザーが「Sankey を表示」ボタンを押したときに、選択中の品目について47ファイルを取得する。取得後は品目単位でキャッシュし、月を切り替えた場合はメモリー上の detail から再集計する。品目を変えた場合は、その品目の Sankey がまだ要求されていなければ自動取得せず、ボタン押下を待つ。既存の選択都道府県 detail キャッシュがある場合は再利用する。

複数ファイルを同時に要求するとブラウザーの接続数や配信元への負荷が問題になりうるため、最大10リクエストずつ順次バッチ取得する。各バッチ内では並列化し、前バッチ完了後に次へ進む。47ファイルすべての取得が成功した場合に限って図を表示し、1件でも失敗した場合は図を表示せず「データを取得できませんでした。再度お試しください」などの案内と再試行操作を表示する。再試行では成功済みファイルをキャッシュから使い、失敗分だけを再取得する。Sankey 用 detail キャッシュは現在選択中の品目の分だけ保持し、品目を切り替えたら前品目のキャッシュを破棄する。既存の選択都道府県 detail キャッシュは別途維持し、一括取得に再利用できる。必要なら AbortController で品目変更・画面破棄時の未完了 fetch を中断する。品目切替や中断後に古いリクエストが完了しても、現在の品目の表示状態・キャッシュを更新しない。

この値は農業生産量ではなく、調査対象卸売市場における産地別卸売数量である。また「産地」は出典上の報告区分（委託者の都道府県）であり、生産地と同義とは限らない。図の見出し・説明・ツールチップでは「産地都道府県別の卸売数量」と表記する。

## 集計と表示の仕様

- 品目と年月は現在のページ選択状態を共有する。Sankey は「Sankey を表示」ボタンを押した後に取得して開く。対象月は地図と同じ選択月とする。
- ソースは選択品目の47 detail JSON。選択月について `value_kind === "reported"` の `raw_value` だけをリンク値（t）として使う。表示単位未満（`below_display_unit`）、事実なし（`no_fact`）、不明・未収集（`unknown_or_uncollected`）はゼロに置き換えず、フローに加算しない。
- 取得済み detail 内で一部の地域・都道府県に数値が欠ける場合は、残った報告値で図を描画し、値種別ごとの欠損セル数を図の説明に表示する。数値報告のない組み合わせはリンクを作らない。detail ファイルの取得に1件でも失敗した場合は部分データの図を表示せず、失敗した都道府県数と再試行案内を表示する。
- 左列は産地都道府県47区分、右列は親区分の主要消費地域9区分。3つの下位地域は親地域の内訳なので重複加算しない（既存 detail は親9区分を出力する）。
- リンク幅を数量に比例させる。都道府県は地方順または総量順、消費地域は固定の地理順に並べる。初期版はノード色を地方別にし、消費地域は中立色で区別する。
- ノード・リンクのホバーおよびキーボードフォーカスで、産地、消費地域、数量、単位を表示する。スマートフォンではラベルと操作が重ならないようにする。
- 図を開く前は Sankey データを取得せず、明示的な「Sankey を表示」ボタンを置く。開いた後は見出しと対象年月、図の後にデータ範囲・欠損値の注記を置く。既存の地図と詳細パネルは維持し、Sankey は地図の下に追加する。

## フロントエンド実装

1. `frontend` に D3 Sankey 用の依存を追加する。基本の D3 と Sankey レイアウト拡張（`d3-sankey`）を使い、必要な型定義も追加する。D3 Graph Gallery の例を参考にするが、現在の Svelte 5 構成に合わせてコンポーネント化する。
2. `constants/types.ts` に集約用の link/node 型を追加し、detail JSON を既存の型で検証する。
3. `useRelayData.svelte.ts` / `fetchRelayData.ts` に、明示操作後の品目別47 detail 取得を加える。最大10件ずつ並列 fetch するバッチ処理、品目別メモリーキャッシュ、途中失敗の記録・失敗分のみ再試行、品目変更・破棄時の中断を実装する。既存の単一 prefecture detail キャッシュがあれば一括キャッシュへ取り込んで重複 fetch を避ける。
4. 純粋関数で選択月の47 detail を `{source, target, value}` のリンクに変換し、reported 数値のみを使う。報告値が `"0"` の場合は線幅ゼロとして描画しない。欠損種別のセル数は別途集計する。
5. `VegetableSankey.svelte` を作り、D3 で responsive SVG を描画する。コンテナ幅変更時にレイアウトを再計算し、Svelte の更新・破棄時に SVG とイベントリスナーを適切に片付ける。`+page.svelte` から明示的な開閉状態、選択品目・年月データ、読込状態を渡す。
6. ローディング、報告値なし、部分欠損、全件取得失敗（図は非表示、再試行案内）の状態を日本語で示す。色だけに依存しないラベル、フォーカス表示、十分なコントラスト、説明的な aria-label を加える。

## 作業順

1. 「Sankey を表示」ボタンと、非表示・読込中・表示済み状態をページに追加する。
2. D3 Sankey 依存、型、47 detail の10件バッチ取得・キャッシュ、集約関数、図コンポーネントを追加する。
3. 既存ページへ統合し、年月・品目選択との連動、部分欠損、空データ、途中失敗・失敗分再試行を実装する。
4. PC・モバイル幅、長い都道府県名、キーボード操作、スクリーンリーダー向け説明を確認する。

## 受け入れ条件

- 任意の品目・月・選択都道府県で、各リンクの値が対応する detail の `reported` 値と一致する。
- 9親地域だけを使い、下位地域を二重計上しない。非数値状態をゼロや数量に扱わない。
- 合計は図で数値化できた報告値の卸売数量を指し、全国の生産量・総流通量と誤解させない注記がある。
- 「Sankey を表示」操作前に47 detail の追加取得や図の描画を行わない。押下後に選択品目の47 detail のみを取得し、一度に未完了の fetch が10を超えない。
- 月変更では再 fetch せず、キャッシュ済み47 detail から再集計する。品目変更後はその品目についてボタン押下まで取得しない。Sankey 用キャッシュは選択中の品目分だけ保持し、品目切替時に前品目分を破棄する。
- detail の取得が1件でも失敗した場合は図を表示せず、「再度お試しください」などの案内と再試行操作を示す。再試行では取得成功済みファイルを再利用し、失敗分のみ取得する。全47件が揃った場合のみ図を表示する。
- 品目・月・都道府県変更で図が仕様どおり更新され、ロード中・空・部分欠損・取得失敗状態が判別できる。
- 図が狭い画面でも閲覧・操作でき、数量はラベルまたはフォーカス可能な詳細でも確認できる。
