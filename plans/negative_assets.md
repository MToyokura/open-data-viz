# 純資産マイナスの世帯数を表示する計画

## 目的と表示仕様

「日本の純資産分布」で、純資産がマイナスの世帯数を他の金額階級と同じグラフ上で確認できるようにする。

現在の「25万円未満」1階級を、公式の再掲3区分に置き換える。表示順は `R01`、`R02`、`R03`、`02`～`19` の21階級とし、初期表示と属性比較の両方に適用する。元の `01` は棒や合計に重ねて含めない。

この実装は、配信用データとフロントエンドの完全な置き換えとする。旧データ（`schema_version: 1`）との互換性は維持せず、新しいフロントエンドはバージョン2のみを受け付ける。旧形式の読み込み、19階級表示へのフォールバック、旧データ単独への切り戻しは実装しない。保存済みの公式API応答は、配信用の旧形式とは別の元データとして再利用する。

今後も、この機能では旧仕様・旧データとの互換性を維持しない。今回の実装では既存コードも確認し、互換性維持だけを目的とする読み込み分岐、形式変換、フォールバック、型定義、テストがあれば削除する。

| コード | 表示ラベル        | 全国・全属性平均の世帯数 |
| ------ | ----------------- | -----------------------: |
| `R01`  | 0万円未満         |                3,973,273 |
| `R02`  | 0万円             |                1,520,744 |
| `R03`  | 0万円超25万円未満 |                1,039,774 |

「0万円未満」は純資産がマイナスの世帯であることを注記する。横軸は引き続き世帯数なので、マイナスの資産階級も正の長さの棒で表示する。負債額別の階級は作らない。

## 根拠と一次資料

以下の公式資料と、保存済みe-Stat API応答を使用する。

- 統計表ID: `0004056120`。<https://www.e-stat.go.jp/dbview?sid=0004056120>
- 公式Excel「第7－131＿1表」: <https://www.e-stat.go.jp/stat-search/file-download?statInfId=000040490406&fileKind=0>
- 総務省統計局「利用上の注意」: <https://www.stat.go.jp/data/zenkokukakei/2024/pdf/riyou2024.pdf>
- 保存済みAPI標本: `data_preparation/inspections/asset_distribution/samples/meta_info.json`、`samples/stats_data.json`。

公式Excelを直接取得して確認済み。全国・年齢平均・学歴平均・年間可処分所得平均・世帯人員平均では、`M10` が `01` の6,533,792世帯、`M29`～`M31` が上記3区分の値となる。API標本の同条件の値も一致する。

統計局資料の別紙3－3「資産額階級」は、純資産総額（純金融資産＋住宅・宅地）がゼロ・マイナスの世帯を最低階級に含むと説明している。世帯数は推計値である。再掲3区分の合計6,533,791世帯と `01` には1世帯の差があるが、公表値を補正しない。同資料の総数と内訳に関する注意に従い、四捨五入で一致しない場合があることを記載する。

## 現在の制約

- `data_preparation/src/modules/projects/asset_distribution.rs` は全36区分を取得済みだが、変換時に `kind == "regular"` の19階級だけを配信用の値に残している。
- 再掲3区分はメタデータと元データに存在するため、保存済み全件応答がそろっていればAPIの再取得は不要。
- `frontend/src/routes/asset_distribution/utils/data.js` のチャンク検証も `regular` だけを許可している。データ生成側と画面側で表示対象をそろえる必要がある。
- 調査記録は「再掲を棒に含めない」「通常19階級」を前提としているため更新が必要。

## 実装手順

### 1. 表示階級をデータ契約で明示する

- `cat04` の分類辞書に、順序付きの `display_category_codes` を追加する。値は公式メタデータの区分名から解決し、上記21階級を設定する。区分が欠ける場合は生成エラーにする。
- `kind` は元の分類の性質を維持する。再掲3区分を通常階級に偽装せず、表示対象と分類種別を別に扱う。
- フロントエンドはコードを独自に列挙せず、このリストを表示順と値検証の共通の根拠にする。重複、未知コード、`01` とその内訳の併存を拒否する。
- manifestと値チャンクの `schema_version` を2へ更新する。生成後の検証処理、型定義、読み込み時のバージョン判定もそろえ、バージョン2のみを受け付ける。バージョン1および未知のバージョンは拒否し、`display_category_codes` がない場合もデータ不整合として扱う。
- データ生成・検証・読み込み・描画と関連テストを調べ、旧仕様・旧データとの互換性維持のためだけに存在する処理を削除する。現時点の `data.js` はバージョン1のみを受け付けており、複数バージョン対応は確認されていないため、今回バージョン2へ置き換える。`asset_distribution.rs` にある旧単一ファイル `asset_distribution.json` の退避・復元処理も用途を確認する。ただし、不要な旧生成物の除去、生成失敗時の出力保護、公式API応答の正規化、調査用標本の生成は互換処理と混同せず、現行機能に必要な処理は維持する。

### 2. 配信用データを再生成する

- Rustの変換処理で、配信対象を `regular` 判定から表示階級リストへ変更する。全36区分の取得漏れ・重複検出は維持する。
- 再掲3区分にも既存の値分類処理を適用する。`-`、`X`、表章単位未満の `0` は既存仕様に従い、数値ゼロへ置き換えない。非数値の値があっても別階級の値から逆算しない。
- 保存済み全件応答から `data_preparation` で `cargo run -- asset-distribution --transform-only` を実行する。元データが欠ける場合のみ公式APIから再取得する。
- 全6,762組み合わせについて21件ずつ、計142,002件の値を出力する。チャンクのバイト数、組み合わせとファイルの対応、サイズ上限を再生成する。

### 3. グラフと注記を更新する

- `frontend/src/routes/asset_distribution/utils/data.js` で、バージョン2の必須項目 `display_category_codes` から表示階級リストを返す共通処理を用意し、チャンクの許可コード・件数検証に使用する。旧形式向けの分岐や `regular` へのフォールバックは設けない。
- `frontend/src/routes/asset_distribution/+page.svelte` と必要に応じて `DistributionChart.svelte` を更新し、一覧・棒・ツールチップ・属性比較の並びを共通の表示階級リストに合わせる。
- ラベルの原文は分類辞書に残し、画面では対象3区分の「（再掲）」を省略する。資産がマイナスでも世帯数は非負であることに沿って軸を維持する。
- 「ゼロ・マイナスは25万円未満に含まれる」という現行注記を、最低階級を公式の内訳3区分に分けている説明に更新する。丸め差、推計世帯数、資産額不詳の扱いも説明する。
- 新形式で表示階級が不足した場合はデータ不整合として扱い、マイナス世帯数を0や未公表と推測して表示しない。
- Svelteの編集時は、この環境のSvelteスキルに従う。

### 4. 文書と配信を更新する

- `data_preparation/inspections/asset_distribution/README.md`、`data_preparation/README.md` を更新し、21階級、再掲の採用理由、二重計上の防止、一次資料での照合結果を記録する。
- 再生成後のmanifest・チャンク容量と、初期表示・代表的な比較操作の転送量を再計測し、調査記録に反映する。
- フロントエンドとバージョン2の配信用データを一組として切り替える。既存の配信手順を確認し、manifestと参照チャンクの世代が混在しない方法で公開・キャッシュ更新する。必要なら世代別ディレクトリを用いる。切り替え前から開いている旧画面は再読み込みによる更新を前提とし、旧画面の継続動作は保証しない。切り戻しが必要な場合もフロントエンドとデータを一組で戻し、新しいフロントエンドで旧データを読む互換処理は設けない。

## 実装時の確認項目・完了条件

- 全国・全属性平均の3区分が公式Excelの上記値と一致する。
- 新形式の各系列が指定順の21階級を持ち、`01`、平均、十分位、最上位再掲を含まない。
- 属性別にも保存済み公式API応答と照合する。`X`・`-`・`0` を含む系列では既存の欠測・秘匿表示を維持する。
- 初期表示、属性変更、複数系列比較で「0万円未満」が表示され、各棒のラベルと世帯数が対応する。狭い画面でもラベルが読める。
- バージョン2の正常な読み込みと、バージョン1・未知バージョン・表示階級リスト欠落の拒否を確認する。表示階級不足、重複、manifestとチャンクの不一致も拒否し、旧形式や19階級表示へのフォールバックがないことを確認する。
- 既存コードと関連テストに、旧仕様・旧データとの互換性維持だけを目的とする処理が残っていないことを確認する。削除した処理と、その役割を調査記録に記載する。該当処理がなければ、その確認結果を記載する。
- Rust側の関連検証と、フロントエンドの `npm run check`・`npm run build` を実施する。既存テストの19階級・形式バージョンの前提を更新し、表示対象の置換と二重計上防止を確認する回帰テストを追加する。
- 公表値の1世帯の丸め差を許容し、合計を一致させるための補正が入っていない。

この作業では計画書のみを作成する。実装・データ再生成・配信は後続作業とする。
