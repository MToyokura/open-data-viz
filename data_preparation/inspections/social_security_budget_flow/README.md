# 社会保障給付費収支表の調査

このディレクトリには、計画書第12章の第0段階で取得したe-Stat応答標本と照合記録を置く。対象は表ID `0004050702`（収入）および `0004050703`（支出）のみ。認証情報は保存しない。

## 調査コマンド

リポジトリルートから `cargo run --manifest-path data_preparation/Cargo.toml -- social-security-budget-flow-inspect` を実行すると、既存の `estat_api` クライアントで両表のメタデータと先頭100件の応答標本を取得する。標本は認証情報を除去して保存する。これは全件取得・本番用原本の代替ではない。

## 調査記録

調査実行後、`inspection.json` に表題、項目・制度分類と確認済み総レコード数を記録する。取得した元応答は表ごとの `*_metadata.json` と `*_sample.json`、取得条件は `inspection_manifest.json` に保存する。現時点でe-Statのメタデータ上、制度は両表とも35項目、収入項目11件、支出項目21件である。データ件数は収入385件、支出735件（全組合せ）と一致した。分類コードは収入 `cat02` が11–20, 41、支出が21–41で、制度コードは `cat01`。通常生成前に、全ページ取得、欠落セル、特殊記号と注記を検証する。

APIの標本応答とメタデータには記号凡例が含まれていない。記号の判定には、対象となる2024年度表のe-Stat画面に掲載された凡例を使い、別統計の規則は流用しない。

## 追加確認と生成状況

通常取得では両表の全値を取得し、`RESULT_INF.TOTAL_NUMBER` と取得行数を照合する。実際に収入385件・支出735件が返り、制度×項目の1,120組合せが揃った。2024年度のe-Stat表画面の凡例では `－` と `―` は「計数のない場合」、`n.a.` は「データなし」、`***` は「数字が得られないもの」とされている。このため `－` と `―` は「計上なし」として図に含めず、未確認事項一覧にも出さない。負値は原則保留するが、「収支差」は収入合計と支出合計の差額と定義されているため、その負値は差額として記録し、フロー図・未確認事項一覧には含めない。

`cargo run --manifest-path data_preparation/Cargo.toml -- social-security-budget-flow` で再取得・変換し、`data_preparation/output/social_security_budget_flow/` に元応答、制度・項目マスタ、1,120件の対応表、根拠資料、未確認事項、32制度分の図データ、フロントエンド用カタログ、生成マニフェストを出力する。取得した元データは保持し、確認済みの凡例と項目定義を表示判定に反映する。Mermaid記法の組み立てとSVG描画はフロントエンドが行う。
