# 属性別純資産額階級別世帯数

## 調査対象と表の意味

- 調査: 総務省統計局「令和6年全国家計構造調査」（調査年 2024年）
- 表: 7-131-1-1「世帯人員(7区分)，世帯主の年齢階級(7区分)，世帯主の学歴(6区分)，年間可処分所得階級(11区分)・年間可処分所得十分位階級(12区分)，資産額階級(24区分)・資産額十分位階級(12区分)別世帯数（年間可処分所得はOECD新基準による）－全国」
- e-Stat 統計表ID: `0004056120`
- e-Statでの公表日: 2026-08-28
- e-Stat HTML: <https://www.e-stat.go.jp/dbview?sid=0004056120>
- 統計局の利用上の注意: <https://www.stat.go.jp/data/zenkokukakei/2024/pdf/riyou2024.pdf>
- e-Stat公式Excel（表7-131-1）: <https://www.e-stat.go.jp/stat-search/file-download?statInfId=000040490406&fileKind=0>

統計局資料の分布指標に関する別紙3-3 (6) は資産額階級を「純資産総額（純金融資産＋住宅・宅地）」に基づくものと定義する。0およびマイナスの世帯は最低階級に含まれ、資産額不詳の世帯は平均にのみ含まれる。このため採用表は純資産総額階級を表し、等価資産額や総資産額の階級ではない。統計局の別紙3-3「資産額階級」では、この最低階級の内訳としてマイナス、0、0万円超25万円未満の再掲3区分が公表されている。

過去の照合記録では、全国・全属性平均における再掲3区分の値は `R01`（0万円未満）3,973,273世帯、`R02`（0万円）1,520,744世帯、`R03`（0万円超25万円未満）1,039,774世帯で、当時の保存API応答と公式Excel「第7－131＿1表」で一致した。いずれも集計用乗率による推計世帯数である。3区分の合計は6,533,791世帯で、通常階級 `01`（25万円未満）の公表値6,533,792世帯とは1世帯の丸め差がある。公表値を補正せず、合計が一致しない場合がある旨を画面に記載する。

世帯数の集計には所得資産集計用の集計用乗率を使う（同資料別紙3-3 (1)）。API値は単純な回答世帯数ではなく、乗率を使った推計世帯数である。e-Stat APIの `VALUE` には `@unit` がなく、表題と表章項目に基づき単位を「世帯」とする。

## 比較集合と組合せの公表状況

- `cat01` は6つの通常年齢区分を比較できる。全体の「平均」は比較集合に含めない。
- `cat02` は `[1, 2]`（在学中・卒業）または `[21, 22, 23]`（卒業者の内訳）を比較できる。APIメタデータの `@level` と `@parentCode` では21～23が「卒業」の下位区分なので、親と子を同じ比較集合に入れない。
- `cat03` は通常所得階級 `01`～`10` または十分位 `R01`～`R10` を別々に比較できる。平均、最上位再掲は含めない。
- `cat05` は6つの世帯人員区分を比較できる。平均は比較集合に含めない。
- `cat04` はグラフの金額階級軸であり、属性比較軸にはしない。

全件応答は243,432セルで、APIページは100,000、100,000、43,432セルの3ページだった。これは `7 × 6 × 23 × 36 × 7 = 243,432` と一致し、4属性軸の6,762組すべてに36区分が存在する。ページ間および全体の重複はなく、取得漏れもない。従ってこの表では属性コードの全6,762組を `published` とし、構造上非公表の組合せは確認されなかった。`-` は組合せの欠落ではなく、当該階級に該当数字がない値としてAPI行に存在する。

## 数値と記号の扱い

API応答は `@unit` を含まず、値は文字列で返る。全件の値は非負整数または公式記号 `-`、`X` だった。APIの `NOTE` は `-` を「該当数字がない」、`X` を「集計世帯数が少ないため秘匿しているもの」と説明する。今回の表示対象21階級に `X` はなかった。

統計局「利用上の注意」別紙4の公式凡例では、`0` は表章単位未満、`-` は該当数字なし、`X` は秘匿を表す。表示階級の6,762系列×21区分では、観測値72,495件、該当数字なし69,483件、表章単位未満24件だった。`0` は数値の0世帯として扱わず `missing` にし、公式凡例を注記する。`-` は `missing`、`X` は `suppressed` とし、いずれも数値0へ置き換えない。今回の表示21階級に `X` はない。API応答にない記号はエラーにする。

全体属性の `cat04=00R`「平均（資産額不詳を除く）」は51,277,351世帯。通常19階級の丸め済み表示値の合計は51,277,352世帯で、1世帯の差がある。この差を補正したり、階級から全体を再計算したりせず、公式の全体値と通常階級を独立して扱う。この表は平均系列を全体に用いており、金額階級だけを分母とした割合は表示しない。

値の照合には、e-Stat公式ファイル「7-131-1」（`statInfId=000040490406`）を使用した。同ファイルの「世帯人員」区分から `平均` の列を選び、年齢 `平均`・学歴 `平均`・可処分所得 `平均` を条件として比較した。資産額のAPI分類コード `00`、`00R`、`01`、`02`、`19` は、それぞれ公式Excelで `平均` 52,688,337、`平均（資産額不詳を除く）` 51,277,351、`25万円未満` 6,533,792、`25～50万円` 732,540、`10000万円以上` 3,304,085。これらは過去の照合結果であり、当時のAPI取得との一致を示す。公式Excelの出典とSHA-256は [`capture_manifest.json`](capture_manifest.json) の公式参照値に記録する。

照合状態は取得ごとに管理する。`crosscheck_history` は過去の照合記録、`official_reference` と `negative_asset_reference` は公式ファイルから保存した比較基準、`current_crosschecks` は今回のAPI取得に対する結果である。現在の照合には、取得時刻、統計表ID、フィルター、API応答全体のハッシュ、比較条件、公式ファイルのURL・識別子・SHA-256を結び付ける。公式基準値と今回のAPI値がコードごとに完全一致した場合だけ `status: "match"` とする。値が変われば `mismatch`、必要な値または基準情報が揃わなければ `unchecked` とし、以前の一致記録を現在の一致証明に転用しない。過去の静的manifestに今回の全API取得応答がない場合、現行状態は `unchecked` のままにする。

## API標本と再現性

`samples/meta_info.json` は `getMetaInfo` 応答、`samples/stats_data.json` は全件取得から抽出した実際の値レコードである。統計データ標本は総数条件と年齢35歳未満条件の各36区分を含む。標本のコード・値は実測値で、アプリケーションIDは含まない。SHA-256とAPI取得条件、ページ数、総件数は [`capture_manifest.json`](capture_manifest.json) を参照。

生成物は `output/asset_distribution/manifest.json` と `output/asset_distribution/items/` 配下の値チャンクである。schema version 3 の manifest はメタデータ、分類辞書 (`dimensions`)、表示順を示す `cat04.display_category_codes`、属性直積の定義 (`combination_index`)、チャンク一覧 (`chunks`) を持つ。属性軸の順序と各軸の区分順から組み合わせを導出し、チャンクの `start_index` と `count` が直積上の連続範囲を示す。組み合わせ一覧やチャンクごとの系列ID一覧は保持しない。値チャンクは指定順の21階級の値 (`items`) を収録する。フロントエンドは version 3 のみを受け付ける。schema version 2、version 1、旧単一ファイル形式との後方互換性はなく、旧形式を読む処理、変換、フォールバックは設けない。再取得には `ESTAT_APP_ID` を環境に設定して `cargo run -- asset-distribution`、保存済み応答の再変換には `cargo run -- asset-distribution --transform-only` を使う。

## 出力サイズと転送量の計測
