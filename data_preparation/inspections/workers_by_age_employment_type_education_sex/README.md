# 年齢・雇用形態・教育・性別別雇用者数: e-Stat API 調査

## 再実行

`data_preparation/` から Rust の調査コマンドを実行します。`ESTAT_APP_ID` は環境変数から読み、出力・ログには出しません。

```sh
export ESTAT_APP_ID="取得したアプリケーションID"
cargo run -- workers-by-age-inspect
# 全レコードの特殊値を再集計するとき
cargo run -- workers-by-age-inspect --scan-all-values
```

`--limit N` で複数レコード標本のページ幅を変更できます（既定値 3）。コマンドは `getMetaInfo`、連続する2ページの `getStatsData`、単一レコードに絞った取得、該当データなしの取得、`$="…"` と `$="0"` の実例を再取得します。`--scan-all-values` を指定すると、表の全レコードをページ取得し、`samples/special_value_scan.json` に件数・代表値・注釈属性の有無を保存します。標本は固定名で上書きし、取得日時と条件を `capture_manifest.json` に記録します。e-Stat の応答に含まれる `PARAMETER.appId` は `[REDACTED]` に置換して保存します。エラー詳細を表示しないため、認証値がログに出ません。

## 確認した表と分類

2026-10-17 UTC の取得では、表 ID `0003006608` は利用可能でした。統計名は「労働力調査 詳細集計　全都道府県 全国 年次」、表題は「年齢階級，教育，雇用形態別雇用者数(2002年～)」、周期は年次です。統計表メタデータは更新日 `2026-09-01`、公開日 `2026-02-13`、収録レコード数 `78,918` を返しました。分類・表示名・順序を含むメタデータ全体は [`samples/meta_info.json`](samples/meta_info.json) にあります。

| API 分類 | 表示名 | 実測内容 | 扱い |
| --- | --- | --- | --- |
| `tab` | 表章項目 | `06` = 15歳以上人口（単位: 万人） | 固定 `06` |
| `cat01` | 年齢階級(詳細集計） | 20区分。コード `00`, `01`, `03`–`20` | 年齢選択肢 |
| `cat02` | 就業状態（詳細集計） | `02` = 就業者のみ | 固定 `02`。年齢・教育・性別・雇用形態と合わせて4つの可変条件にできる |
| `cat03` | 雇用形態 | 12区分（`00`, `02`–`12`） | 雇用形態選択肢 |
| `cat04` | 教育 | 11区分（`00`–`10`） | 教育選択肢 |
| `cat05` | 性別 | `0` = 総数、`1` = 男、`2` = 女 | 性別選択肢 |
| `area` | 地域 | `00000` = 全国のみ | 固定 `00000` |
| `time` | 時間軸（年次） | `2002000000`–`2025000000`、2002–2025年 | 年の取り出しには末尾の固定ゼロを除き、値を数値として扱う |

雇用形態のコードは `00` 雇用者、`02` 役員を除く雇用者、`03` 正規の職員・従業員、`10` 非正規の職員・従業員、`04` パート・アルバイト、`05` パート、`06` アルバイト、`07` 労働者派遣事業所の派遣社員、`08` 契約社員・嘱託、`11` 契約社員、`12` 嘱託、`09` その他です。年齢・教育の全コードと表示名はメタデータ標本を参照してください。これらを手書きで固定する場合も、コード値だけでなく分類順序をメタデータに合わせます。

表の分類には独立した「就業状態」と「雇用形態」の両方がありますが、`cat02` は実測上 `02` 就業者の1分類だけです。就業状態を別の選択肢として見せず、取得条件に常に `cdCat02=02` を指定します。

## 応答形式とページング

メタデータの `METADATA_INF.CLASS_INF.CLASS_OBJ` は軸オブジェクトの配列です。各軸は `@id`、`@name`、`CLASS` を持ちます。`CLASS` は1分類だけの `tab`、`cat02`、`area` ではオブジェクト、複数分類では配列でした。`@code`、`@name`、`@level` が分類の基本項目で、`tab` の分類には `@unit` もあります。従って、Rust 側で `CLASS` を常に配列と仮定せず、単一オブジェクトも受け入れる必要があります。

統計データは `STATISTICAL_DATA.RESULT_INF` に件数とページ境界を持ち、`DATA_INF.VALUE` にレコードを持ちます。標本の複数レコード応答では `VALUE` は配列、分類と時間をすべて指定した1レコード応答では `VALUE` は単一オブジェクトでした。値オブジェクトの分類コードは `@tab`、`@cat01`–`@cat05`、`@area`、`@time`、単位は `@unit`、値は `$` です。代表値 `5337` は `2002年`・15歳以上人口・単位「万人」を示します。応答標本は [`samples/stats_data_start_1_limit_3.json`](samples/stats_data_start_1_limit_3.json)、[`samples/stats_data_single_filtered.json`](samples/stats_data_single_filtered.json) を参照してください。

ページングでは `limit=3`、`startPosition=1` が `TOTAL_NUMBER=78918`, `FROM_NUMBER=1`, `TO_NUMBER=3`, `NEXT_KEY=4`、続く `startPosition=4` が `FROM_NUMBER=4`, `TO_NUMBER=6`, `NEXT_KEY=7` を返しました。境界レコードは2004年から2005年へ連続し、重複はありません。実測上、`cntGetFlg=Y` は `TOTAL_NUMBER` を返しながら `DATA_INF` を空文字列にしたため、観測値取得にはこのフラグを指定しません。通常の観測取得では `metaGetFlg=N` を指定し、必要なメタデータは別途 `getMetaInfo` で取得します。

該当データなしの標本では `RESULT.STATUS=1`、`RESULT_INF.TOTAL_NUMBER=0` で、`DATA_INF` 自体が省略されました。条件は表章項目 `06`、年齢 `20`、就業状態 `02`、雇用形態 `03`、教育 `10`、性別 `2`、全国 `00000`、2002年です。実際の応答は [`samples/stats_data_no_data_filtered.json`](samples/stats_data_no_data_filtered.json) にあります。API が返す「データなし」と、`DATA_INF.VALUE` 内に値があり `$` が特殊値である欠損は別の状態として処理してください。

`DATA_INF.NOTE` は先頭ページに4件あり、注記コード `*`（分母が小さいため比率を計算していない）、`***`（該当数値なしまたは集計なし）、`0`（数値が表章単位未満）、`…`（東日本大震災の影響による掲載なし）の説明を含みます。全 `78,918` レコードを `limit=10000` のページで走査したところ、`$="…"` が4,140件、`$="0"` が11,814件ありました。`$="*"` と `$="***"` は観測されませんでした。件数と例の再確認には [`samples/special_value_scan.json`](samples/special_value_scan.json) を参照してください。`$="0"` は値オブジェクトに `@annotation` 属性が付かず `DATA_INF.NOTE` の共通注記だけが返るため、数値ゼロとは解釈せず「表章単位未満」の注記付き欠損として扱います。確認例は [`samples/stats_data_special_value.json`](samples/stats_data_special_value.json)（`$="…"`）と [`samples/stats_data_zero_value.json`](samples/stats_data_zero_value.json)（`$="0"`）です。`…` の意味と `0` の表章単位未満の意味は `NOTE` で説明されます。観測値の `@unit` は「万人」です。

`DATA_INF` が空文字列になる形式も `cntGetFlg=Y` で実測しましたが、それは観測レコードを返さないAPI呼び出しの結果です。`DATA_INF` 省略はゼロ件の標本で観測しました。どちらも正常なデータ配列と同じ扱いをしてはいけません。

## 未確認事項

- 特殊値の件数は今回取得した78,918レコードに対する走査結果です。API側のデータが更新された場合は再走査してください。今回、値オブジェクト上に `@annotation` 属性は見つかりませんでした。
- 公開後の将来更新で分類や収録期間が変わる可能性があります。生成時にメタデータを読み、年や選択肢を固定リストにしない前提です。
- この調査で確認した `NEXT_KEY` は小さい limit による先頭2ページの連続性です。全件取得時にも各ページの件数と境界を照合してください。
